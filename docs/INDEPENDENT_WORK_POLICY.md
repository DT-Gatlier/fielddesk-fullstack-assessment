# Independent work and no-AI policy

Policy version and effective date: **11 November 2026**.

## Requirement

Complete the assessment independently, without AI-assisted tools. This applies to planning, architecture, code, database design, debugging, testing, configuration, documentation and explanations submitted for review.

Do not use AI chatbots, coding agents, generative code completion, AI code review, AI-generated search answers or other generative assistance for this assessment. Examples include ChatGPT, Codex, GitHub Copilot, Claude, Gemini and AI features in editors such as Cursor. These examples are not exhaustive. Disable generative AI features before starting. Do not submit AI-generated work obtained from another person or reuse another candidate's solution.

## Permitted resources

- Official documentation, books, tutorials and ordinary web search results, without generated AI answers.
- Standard libraries, package managers and non-AI framework scaffolding or migration generators.
- Conventional IDE symbol completion, navigation, formatters, linters, compilers, debuggers and test runners.
- Small non-AI reference snippets where licensing permits reuse. Identify sources and adaptations in your technical notes; do not copy a complete assessment implementation.

You must understand and be able to explain and modify all submitted work. Normal framework-generated files are not, by themselves, evidence of generative AI use.

## Declaration and questions

Complete `candidate-submission/AI_USAGE.md`, now the independent-work declaration. The filename is retained for existing links and forks. Tick confirmations only when personally true.

If prohibited assistance has already been used, stop and contact Gatlier. Describe the tool, purpose and affected work honestly. Do not sign a false declaration or remove history to conceal use. Disclosure does not make an AI-assisted submission compliant. A fresh assessment is at Gatlier's discretion, not automatically offered.

Raise general questions through a repository Issue before proceeding. For private candidate circumstances, reply to the invitation email. Do not publish private correspondence or personal information in an Issue.

## Evaluation

Compliance is an eligibility requirement, separate from technical scoring. Confirmed prohibited assistance makes a submission ineligible even if its code works. Resolve an incomplete declaration before progression.

Reviewers may examine disclosures, relevant commit history, submitted artifacts and candidate explanations, and require a supervised no-AI walkthrough or modification. Code style and automated AI-detector scores alone are not sufficient proof. Final recruitment decisions remain with Gatlier's hiring team.

## Effective date and conflicting instructions

This policy applies to new assessments issued under this version from 11 November 2026. Older template wording permitting AI does not apply to new invitations under this policy.

For assessments already issued or submitted, record the instructions actually communicated and any written clarification. Do not retrospectively treat previously permitted assistance as prohibited. If invitation and repository instructions conflict, request written clarification before starting or continuing; do not assume which rule applies. HR must explicitly resolve existing conflicts.

An exception concerning Docker, deadlines or technology choices does not authorise AI assistance.

## Wording for new invitations

Use this wording and link this policy:

> AI-assisted tools are not permitted for any part of this assessment, including planning, implementation, debugging, tests and documentation. Complete the work independently and submit the independent-work declaration. Ordinary documentation and non-AI development tools are allowed as described in the repository's independent-work policy, version 11 November 2026. Ask for written clarification before proceeding if any instructions conflict.
